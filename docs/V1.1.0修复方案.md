## 一、修复项与设计

### S1 编辑器预览：3D 舞台正确渲染（缺陷 #1）

> **终局根因（实施期实验定位，推翻初版与审查版的机制推测）**：编辑器启动时 `Component.onCompleted` 里 `app.startupPlan` 若判定 journal 未闭合（脏 journal），会**在窗口首帧渲染前**弹全屏崩溃恢复模态框（`RecoveryDialog`/`ModalLayer`，z=2000 的全屏遮罩）。在 Qt 6.11 + D3D11 下，首帧前出现全屏遮罩会**永久毒化该窗口的 Qt Quick 3D 合成**（View3D 场景图照常运行、renderStats 144fps，但纹理永远不上屏），且关闭模态后也不恢复——编辑器预览的蛋糕因此整个会话消失。播放器不加载编辑器 UI，不受影响。初版的「View3D 不支持祖先 scale」与审查版的「Underlay 合成错位」推测均被实验否定（同结构在新窗口、播放器窗口、甚至缩放/裁剪/层级全开时都正常渲染）。
>
> 实验链（.tmp-qa/ 探针可复现）：裸 Cake3DStage 窗口✓ / 复刻 PreviewStage 完整嵌套的新窗口✓ / 播放器+任意缩放✓ / 真实编辑器✗ / 精简到只剩 PreviewStage 的编辑器✓ / 恢复 startupPlan 尾巴✗ / 只把模态 open 推迟到首帧后✓。

**改动**（两层防御 + 一致性）：
1. `app/qml/Editor.qml`：startupPlan 的模态弹窗（recovery/wizard/newDialog）改为**挂钩窗口 `afterAnimating` 首帧信号 + 500ms** 后再执行（`sawFirstFrame` + `Connections` + `startupPlanTimer`）——确定性避开「首帧前全屏遮罩」这一毒化条件，恢复流程本身保持不变。auto-open 的 `session.openProfile` 一并延迟（无害且统一）。
2. `app/qml/show/Cake3DStage.qml`：`renderMode: View3D.Offscreen`（3D 渲进独立 FBO 再作为普通纹理合成，对变换/合成顺序更稳健；编辑器与播放器统一路径，播放器回归已验证）。
3. journal 卫生（防复发的体验层）：用户上次异常退出后 journal 保持脏状态是**每次启动弹恢复框的正常设计**（E-06），修复后弹框不再毒化 3D；QA 侧注意：探针强杀进程会弄脏 journal，测试后需 `mark_clean_exit()` 还原。

**验收口径**（已自测通过）：脏 journal 启动→模态延迟弹出→关闭→蛋糕预览正常渲染（蛋糕色像素 n≈2900/4734 量级）；干净 journal 启动直开配置档→正常；zoom 50/100/200 均正常（n=1790/4734/4733）；播放器 `--play` 窗口蛋糕 31k 像素不回归；单测 9/9 通过。

### S2 蛋糕交互：旋转方向、持久旋转、果冻叠加、操作提示（缺陷 #3/#4）

改动 `app/qml/show/Cake3DStage.qml`（`Cake2DStage.qml` 仅同步果冻振子——2D 是单张贴图，无旋转/公告板概念）：

1. **旋转方向修正**：`dragYaw = dragStartYaw - translation.x * 0.02`（拖右→蛋糕正面随手转向右）。pitch 同步翻转并放宽到 ±12°。
2. **取消自动回正，保留惯性**：删除 `dragReturn`（SpringAnimation 无法注入初速度，审查已确认不可行）。惯性复用 S2.3 的 FrameAnimation 积分器：拖动中在 `onTranslationChanged` 里差分角速度 `dragVel`；松手后积分 `dragYaw += dragVel*dt; dragVel *= exp(-2.6*dt)`，`|dragVel|<0.02°/s` 时停。dragYaw 解除 ±14 钳位，累计后按 360 整倍数回绕到 (−180,180]，支持整圈旋转。
3. **果冻叠加（调研选型：FrameAnimation 阻尼振子；有意偏离 F-17.5 的 SpringAnimation 字面规格——vector3d 属性无法挂 SpringAnimation，且 SequentialAnimation 不支持叠加，偏离记录进 RELEASE_NOTES）**：
   - `jellyX`（形变量）、`jellyV`（速度）；每帧 `jellyV += (-k*jellyX - c*jellyV)*dt; jellyX += jellyV*dt`，**dt 钳位 ≤1/30s**（窗口拖动帧尖峰保护）。
   - k=spring×14、c=damping×6（默认 4.2/0.42 → ω≈7.7 rad/s，单击 ~0.9s 两三个过冲）。
   - `jelly()` 改为**速度冲量 `jellyV += 2.0`**（审查修订：初版 5.2 的无阻尼峰值 0.68 必然顶死钳位，单击即饱和、叠加验收不可能通过；2.0 → 峰值 ≈0.26）。形变量钳位 ±0.32、速度钳位 ±8（体积守恒 squash：scaleY=1−x，scaleXZ=1+0.6x）。
   - FrameAnimation 仅在 `|jellyX|>0.001 || |jellyV|>0.01` 时运行，静止零开销；`reducedMotion` 不弹（F-26）。
4. **火苗公告板与「风摆」解耦（审查新增必改点）**：`flameNode`/`smokeNode` 的 `eulerRotation.y` 补偿改为 `-(camCfg.yaw + dragYaw)`；同时 `Cake3DStage.qml:432-433` 火苗摆动幅度 `-3 - root.dragYaw … 3 + root.dragYaw` 直接绑定 dragYaw——解除钳位后会放大到 ±180°+ 导致火焰翻转，改为独立有界的 `windTilt`（拖动角速度驱动，钳 ±8°，松手衰减）。
5. **操作提示（缺陷 #4）**：`ActCake.qml` hint 胶囊增加一行副提示「**拖动可旋转蛋糕 · 点击蛋糕会弹起来**」（opacity 0.55、13px，随主提示 7s 后一起淡出）。胶囊高度 64→88、外层 Item 68→92（审查指出三行文字 64px 装不下）。schema 新增 `CakeAct.interaction_hint: str = "拖动可旋转蛋糕 · 点击蛋糕会弹起来"`（≤40 字），检查器加文本字段。

**验收口径**：探针注入模拟拖动事件序列验证 yaw 符号与无回正；连续注入 3 次点击间隔 120ms，jellyX 峰值 > 单次点击峰值（叠加生效，参数已按审查修订保证数学可达）；火苗摆动幅度在任何 dragYaw 下 ≤±10°；hint 三行完整显示且 7s 淡出。

### S3 便签：溢出线修复 + 蜂群呈现（缺陷 #2/#5）

#### S3a 溢出线（PopupCard.qml + ActConfirm.qml，实施前已像素实证）

> **实证结论（.tmp-qa/card_overflow_probe2.py，修复前基线）**：单卡在绿幕上扫描 bbox 外像素——cartoon 底部 2 行越界（阴影，854px）、glass 底部 3 行（两层阴影，1345px）；**顶部/左右均无越界**（cartoon 胶带确被 shell clip）。用户所述「上边一条线」最可能是沿轨迹排列时**相邻上一张卡的底阴影条**出现在视线中卡的上缘外——修复底阴影后该现象一并消除。

- **已修**：`PopupCard.qml` 两层投影矩形改为完全收入卡内（height 收边至卡底）；`ActConfirm.qml:51-59` 确认卡阴影同源修复；cartoon 胶带 `y:-6 → y:3`（旋转包络也收入）；glass 卡在 shell 内加 3px 内底部暗渐变（被 clip）补偿层次。LetterView 信纸软 PNG 阴影（羽化边缘）检查后保留。
- **修后复测**：cartoon/glass 两风格、上下左右四向越界像素均为 0。

#### S3b 蜂群便签（新增呈现层）

**产品定义**：幕3 开场先由数百枚小号便签沿轨迹曲线快速连续浮现（每枚间隔 12–20ms），相邻便签互相重叠 90% 左右，首尾相接把轨迹「描」成一条由便签构成的粗线/爱心轮廓；曲线成形后，原有可读祝福卡（F-05）再依次飞入停留。低动效模式保留成形过程但去掉弹出动画（F-26）。

**Schema**（`app/config/schema.py` `PopupsAct` 新增子模型）：

```python
class SwarmConfig(StrictModel):
    enabled: bool = True
    count: int = 320          # ge 40, le 400（性能预算内，见下）
    note_size: int = 44       # ge 20, le 90
    overlap_pct: int = 90     # ge 50, le 98，期望重叠度（用于步长推导）
    stagger_ms: int = 14      # ge 4, le 60
    fade_in_ms: int = 120     # ge 40, le 600
    jitter_px: int = 6        # ge 0, le 30，位置/旋转抖动去机器感
    cards_delay_after: bool = True   # 曲线成形后可读卡再出场
```

默认 `enabled=True`：与用户「要的就是这个效果」一致；旧配置档缺省即获得蜂群（schema 默认值填充，无需迁移）。

**轨迹**（`Trajectory.js` 新增 `dense(preset, count, span)`）：对 heart 用参数方程 `heartPoint(t)` 按**弧长均匀**采样 t∈[0,2π)（顺序：从心尖起笔沿一侧轮廓上行、经顶谷、另一侧下行收于心尖，一笔连成）；circle/spiral/wave/arc/diagonal 同样给出参数化稠密采样。步长 = 弧长/count；若步长 < note_size×(1−overlap/100) 则按 overlap 下限放大步长并提示实际覆盖率（默认参数在 1080p/span 0.72 下实测调到整圈成形）。位置仍过 `clampPoint` 防出界。

**渲染**（`ActPopups.qml` 新增 swarm 层）：

- 每枚便签 = 1 个 `Item`（旋转 jitter −8…+8°）内 2 个 `Rectangle`（本体 + 顶部 6px 深一档的"胶带条"），纯色无 shader/无 Canvas/无阴影——320 枚 ≈ 640 个静态图元，远低于 2D 层 60fps 预算（10.1）；同屏玻璃卡上限 7/12 的约束（density.maxLivingPopups）只管可读卡，不适用蜂群（蜂群是"轨迹描线"类内容，与 F-23 confetti 同级， ≤400 枚上限即预算声明）。
- 颜色：`colors.harmony()` 一次性生成 count 份（沿用谐和色板 F-33，亮度/饱和度桶，杜绝亮度参差）。
- 出场：Timer 按 stagger_ms 逐枚把 `spawned=true`；便签 opacity 0→1（fade_in_ms）+ scale 0.82→1（90ms，reducedMotion 关闭）；无 bob 浮动（静态描线）。
- **创建方式（终局修复，验收发现 340–400 枚会在 ShowStage 单帧创建时死锁）**：Repeater 的 model 绑定 `swarmSpawned`，**每 14ms 增量创建 1 枚**（不再一帧建完）；`swarmTimer` 用墙钟追赶（`Math.floor(elapsed/stagger)+1`）抵消 Windows 15.6ms 定时器量化；可读卡在 `onSwarmComplete()`（蜂群**实际**完成时）后才启动；`cards_delay_after=false` 时卡片与蜂群并行（总时长取 max）。实测 320/340/360/380/400 各 5 次全部成功，320 耗时 4.53s。
- **退场（审查修订：幕3 结束必须显式淡出）**：现状进幕4 时 ActPopups 不卸载、confirm 叠加压暗——蜂群若常驻会带着 320 枚便签贯穿整个幕4 直到 dissolve 冻结。因此在 `finish()`（holdTimer 触发或 skip 时）将蜂群层 600ms 淡出；可读卡维持现状（各自 lifetime 渐隐）。
- **可读卡顺延**：`cards_delay_after=true` 时在 QML 侧给卡出场 Timer 加延迟 `count×stagger + fade_in`（≈4.6s）——**不写回 `start_delay_ms` 字段**（schema le=4000，写回必炸校验）；`validator.py` 时序 lint 同步纳入蜂群时长，避免系统性低估入场总长。
- skip()：蜂群与卡全部立即现身（reveal 语义），随 finish 淡出。

**编辑器**（`InspectorPane.qml` 祝福页新增「蜂群便签」分区）：enabled/count/note_size/overlap_pct/stagger_ms/jitter_px/cards_delay_after 七个字段。

**验收口径**：几何断言（无越界子项）+ 探针采样幕3 中段画面：轨迹带上便签色像素覆盖率、相邻采样中心距/尺寸比 ≈ 10%（重叠 90%）；QML 无告警；帧率不劣化（目测流畅即可，无掉帧日志）。

### S4 开场门禁：启用按钮 + 暗色（缺陷 #6）

**Schema**（`IntroAct` 新增）：`gate: bool = True`、`gate_text: str = "开启这份祝福"`（≤16 字）、`gate_subtext: str = "一份心意，正在等你点开"`（≤30 字）。

**呈现**（`ActIntro.qml`）：

- 初始：全屏暗幕（`#0a0714`，opacity 0.96，盖过 BackgroundStage 形成「未开启」暗色），中央一枚玻璃质感胶囊按钮（高 64、内边距 ≥44px 满足 targets.primary；hit target ≥96px 与 F-03 同规格），下方 gate_subtext（16px、opacity 0.6）；按钮外圈光晕采用**尺度呼吸**（scale 1.00↔1.025，周期 ≥3s）而非亮度呼吸——亮度零变化，彻底规避 F-27「单次亮度变化 <10%」的严格读法（审查修订）；reducedMotion 时光晕静止。
- 点击/空格/回车：`sfx("chime")` → 暗幕 600ms 淡出 + 按钮缩放淡出 → 信封按现有流程浮现（envelope.opacity 0→1）。信封出现后走既有「轻触信封→幕2 火漆」链路，两步仪式保留。
- **键盘路径分支（审查修订）**：现状 `ActIntro.qml:58-63` 根 Item Keys.onPressed 的 Space/Enter 直达 `advance()`——门禁未开时必须先开门而不是跳过整幕；`Component.onCompleted` 的 `envelope.opacity=1` 也要按 gate 状态分支（门禁开→按钮态，否则信封态）。
- **skip 语义（审查要求写死）**：不给 ActIntro 加 skip()，维持现状——跳过=跳过整幕直达幕2（F-29 每幕可跳过），门禁不拦截跳过。
- BGM 维持现状：策划案 F-01/第四章原文「启动即播仅限本地 exe 场景……幕1 **支持** on-tap 进入」是允许而非强制，门禁承担「用户在场」确认，惊跳预防语义已满足（引用原文，防复审反复）。
- `gate=false` 时行为与 v1.0.0 完全一致（向后兼容开关）。
- 键盘可达：按钮 `activeFocusOnTab`，Space/Enter 激活（2.1.1 键盘可达基线）。

**编辑器**：开场页新增「开场门禁」分区（gate/gate_text/gate_subtext）。

**验收口径**：探针确认幕1 首帧无信封、存在按钮；模拟点击后 1s 内信封可见；skip/低动效/高对比路径不回归。
